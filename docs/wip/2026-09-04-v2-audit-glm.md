## 2. Smallest V2 architecture that delivers the references

Principle: every reference element either (a) composes over existing
services/models, (b) needs one additive seam, or (c) is a one-way product
decision (§7) and is excluded from the architecture. Nothing in the ten
references requires a new process, a new dependency, a server, or a rewrite
of the capture pipeline.

**Six real seams — everything else is view composition:**

1. **Playback layer** (`AudioPlayerService`, MainActor `@Observable`
   wrapping `AVAudioPlayer` + position publisher). Needed by refs
   01/05/08/10 (player bar, seek, ±15 s, speed, per-line play, chapter
   jump) and dictation cards' play buttons. No schema change; reads
   `meeting.audioMicPath`/`audioSystemPath` (mixing mic+system playback is
   out of the smallest slice — refs' single waveform maps to the system
   channel or a chosen channel per session).
2. **Waveform peaks** — downsampled RMS peaks computed at capture time by
   the existing per-buffer RMS pass (the value already exists at
   `RecordingSession.handleMic/handleSystem`; only persistence is new) and
   post-hoc for legacy meetings by one AVAudioFile scan (same pattern as
   `FileMeetingTranscriber.probeChunks`). Stored as a sidecar JSON/blob next
   to the m4a (`AppPaths.audioDirectory`) or a blob column; ≤ 5 peaks/s.
   Replaces the fake `MeetingSparkline` data only where real peaks exist.
3. **Transcript windowing + search** — keyset-paginated `fetchSegments`
   (LIMIT/cursor on `startSeconds`), SQL text search and speaker filter.
   Needed by refs 01/06 (582-line transcript, "Showing 1–50", ⌘F, All
   speakers, 78 results, auto-scroll toggle, jump-to).
4. **Dictation entry metadata — migration v9** (append-only; nullable
   columns decode old rows unchanged, mirroring the `ActionItem.done`
   precedent): `title`, `languageID`, `favorite`, `tagsJSON`,
   `waveformPeaksJSON` (+ keep `durationSeconds`, `wordCount`, `sourceApp`
   already stored). Language is known at commit time from the engine
   (`DictationController` locale) — no AI needed for v1 cards.
5. **Bookmarks / key moments — migration v10**: one table
   (`meetingID, startSeconds, label?, createdAt`) written by ⌘B during
   recording (refs 01/04/05/08) and rendered as chapter markers on the
   player and Key Moments sections. LLM-generated moments are a later
   additive prompt field (see seam 6), not required for the UI.
6. **Enhancement output extension (additive parse)**: `decisions`,
   `outcomes`, `moments` as new optional keys in the strict-JSON prompt;
   stored in new nullable meeting columns or parsed out of the report —
   additive either way, because the parser already tolerates absent keys
   (`EnhancementResult`). Needed by refs 05/08/10 Overview cards. Also
   `ActionItem.dueDate: String?` (additive decode).

**Explicitly not seams** (composition over what exists): three-column
shell (sidebar exists at 248 pt; add trailing contextual panel as a SwiftUI
detail-layout choice); Overview tab (summary + action items + moments over
existing columns); permission health banner (compose `PermissionCenter`
states — it already exposes every state the reference shows,
`PermissionCenter.swift:16-88`); dictation stats (already
words/WPM/apps/saved via `dictationStats`); live recording stage (timer,
rings, levels, Stop, mark-moment, quick note — all existing state; only the
view is new); talk-time speaker breakdown (SQL GROUP BY speaker over
segments); sidebar folder counts (`folderMeetingCounts` already exists, just
not wired to the sidebar).

**Architectural invariants preserved:** single MainActor orchestrator; audio
pipeline untouched (its CPU history is the repo's most expensive lesson);
timestamps stay meeting-relative seconds; migrations append-only; Speech
analyzers stay one-at-a-time / post-stop by default; no new top-level
dependency.

## 5. Lifecycle / cancellation / backpressure rules (per subsystem)

**Dictation.** Exactly one capture at a time; a meeting recording wins
(`micBusy`, `DictationController.swift:161`). `cancel()` bumps
`sessionGeneration`, finishes the continuation, stops the mic, hides the
overlay, restores captions (84-97). `stop()` finishes the continuation,
stops the mic, then `await transcribeTask.value` (232-242) — engines observe
stream-finish, not task cancellation, as their terminator. Rule for V2: any
new UI surface (docked live panel, cards) observes `DictationController`;
it never starts a second capture. The chunk stream is `.unbounded`
(`beginCapture`, 162-164): acceptable only while the consumer is a live
analyzer; rule — no new consumer may subscribe without a drain guarantee.

**Recording.** Start is cancellable at three `Task.checkCancellation`
points (`RecordingEngine.swift:67-75`); stop serializes teardown on
`controlQueue` with a final `writer.sync` (`RecordingSession.stop`,
252-268) so no write races file nil-ing. Restart budgets: mic restarts < 8
per recording, system-tap retry ≤ 1, Muse reconnects ≤ 5 (verified
`RecordingEngine.swift:102-152`, `SystemTapRetryPolicy`, `MuseSystemTranscriber`).
V2 rule: waveform peaks and bookmark capture join as observers of existing
callbacks — they must not add work to the IOProc/critical path and must not
introduce new restart paths.

**Live transcription.** `finishAndWait` cancels the volatile flush, forces
the language decision, and awaits channel tasks by index (appends during
await are tolerated, `TranscriptionCoordinator.swift:134-155`). `ChunkFan`
drops dead consumers via `onTermination` (517-519) — yield never buffers
into an unread stream. Rule: keep the single-start-locale policy; adopting
a locale is irreversible per meeting (464-495).

**AI jobs (enhancement, diarization, inference, rewrite).** Per-meeting
reentrancy guard via `enhancingMeetingIDs` (`AppState.swift:487`), but no
global serialization: two meetings can run CLIs concurrently, and Swift
task cancellation does not terminate a running CLI — only the 600 s
watchdog `terminate()`s (`LLMRunner.swift:116-121`; V — `runSync` never
checks cancellation). **Guard before adding any new AI trigger (live AI,
regenerate button, per-dictation titles): a job owner that serializes per
provider and propagates cancellation as process termination.** The API's
`enhanceTrigger` already fires detached MainActor tasks (`APIServer`
closure, `AppState.swift:236-240`) — same owner must absorb it.

**Inspectors/watchers.** Every timer in §1.3 has a verified cancel path
except the calendar loop, which runs for the app lifetime by design.
`deleteMeeting` removes DB rows but not the audio directory (orphan source,
V, `AppState.swift:648-659` + 272 MiB on disk) — V2 retention work must
take a product decision first (§7.3).

**Backpressure.** Two unbounded paths exist: the session writer queue
(every audio buffer deep-copied and enqueued; long gaps append silence in a
synchronous loop on the writer queue, `RecordingSession.swift:299-319,
399-415`) and the fan/dictation streams (AsyncStream default unbounded).
Neither has shown loss or unbounded growth in evidence, but both are
🔴 persisted-media surfaces (V-prev audit): rule — measure (§4 memory/DB
budgets) before touching; coalescing/padding changes are proposals until a
recording profile proves the need.

## 6. Test strategy — observable E2E and real GRDB paths first

Current suite (V): 197 tests / 37 suites / 2,800 LOC, green at `c7704c3`.
Real paths already proven: in-memory GRDB with real migrations
(`AppDatabaseTests`), live TCP against the real API server
(`APIServerIntegrationTests`), real subprocess execution
(`LLMRunnerTests` — non-zero exit, timeout termination, large-stdin
deadlock), real AVAudioFile write/gap-pad (`MicContinuityTests`), Speech
boundary fakes (`FileMeetingTranscriberTests`). This is the right spine;
V2 extends it, no new framework.

Priorities for V2, in order:

1. **Data/contract first (ranks 1–2 of blast radius):** migration + round-trip
   tests for v9/v10 on a database migrated through all prior versions
   (not a fresh v-latest DB — the append-only order itself must be covered);
   keyset-pagination and search tests with a 10k-segment fixture; peaks
   round-trip; `ActionItem.dueDate` decode of pre-V2 JSON.
2. **Player as observable contract:** state machine tests (play→seek→end,
   speed changes, seek while paused) against real files produced by the
   existing m4a writer — one real audio fixture beats five mocked units.
3. **E2E-ish smoke without TCC:** record-with-hardware cannot run in CI;
   the established substitute is `ingestMicBufferForTesting`
   (`RecordingSession.swift:150-156`) — extend that seam for peaks and
   bookmarks so capture-adjacent logic is testable without a mic.
4. **API surface as E2E:** the local API already exposes meetings; new
   pagination/moments should extend `APIRouter` contract tests where the
   reference features create externally visible state (bookmarks, pages).

**Exact missing guards to write BEFORE the risky changes:**

- **G1** (before C2/C14 touch anything near the audio path): a writer-path
  test asserting file-time == meeting-time across a synthetic gap, using
  `ingestMicBufferForTesting` — protects the timeline contract the audit

## 7. One-way decisions (alternatives, reversibility, risk, what proceeds)

None of these is decided by this audit. Each blocks only the listed items.

**7.1 Local vs cloud AI.** Status quo: on-device Apple ASR default, CLI
subscription auth for enhancement, opt-in Muse cloud for system channel /
dictation (V, `MeetingASRPolicy`, Settings). References show both an
"On-device" badge and cloud-flavored features. Alternatives: (a) keep the
hybrid with explicit badges — reversible, no new dependency; (b) all-local
ASR enhancement (new ML dependency, large) — hard to reverse once prompts
and output formats target it; (c) cloud-first — privacy and retention
consequences, effectively one-way for user trust. Blocks: live AI (7.4),
"accuracy 96 %" stat (needs scored ground truth either way). Proceeds
without it: every UI seam, playback, waveform, pagination, bookmarks,
permissions, talk-time.

**7.2 Integration auth (Slack/Notion/Linear/Jira cards, linked docs,
"+ Add integration").** No OAuth client, no token flow, no external HTTP
except Muse/webhooks exists today (V). Alternatives: (a) defer — render
nothing; (b) read-only deep links (no auth, no one-way door); (c) real OAuth
apps per vendor — client IDs/secrets are registry artifacts, scopes are
reviewed by vendors; reversing means dead UI for users who connected.
Blocks: sidebar Integrations section, Linked Documents, "Synced to". All of
§3 proceeds without it.

**7.3 Audio retention.** `audioRetentionDays` exists, default keep-forever;
deleting a meeting keeps its audio (orphans, §5). References push a storage
meter. Alternatives: (a) explicit user-set retention + orphan sweep behind
a confirmation — destructive once run; (b) "waveform+transcript only" mode
(audio deleted after processing; peaks survive) — the natural V2 companion
of seam 2, but irreversible per meeting; (c) status quo. Blocks: storage
card, quota display, orphan cleanup. Proceeds: player, peaks, everything
else (peaks make (b) possible later, which is why seam 2 stores peaks
outside the m4a).

**7.4 Live AI during meetings (live summary, live action items).** Depends
on 7.1; new CPU/network load during the exact phase with the hang history;
prompt/output contract evolves live. Reversible technically, not in user
expectations once shipped. Blocks: ref 04's AI Assistant panel content
(panel shell can ship showing live transcript only). Proceeds: live stage,
live transcription panel.

**7.5 Localization of the UI.** All strings are English literals (V).
Alternatives: (a) ship English (ES content already works end-to-end);
(b) String Catalog + ES now — cheap at ~dozens of strings, cost grows with
every added string, so it must be decided at V2 start, not after;
(c) catalog later = re-touch every view. Reversible but monotonically
expensive. Blocks: nothing functional; blocks only the ES UI.

**7.6 Video.** References mention "HD Video & Audio" and Screen Recording
for OCR. Screen capture is a new TCC surface, storage order-of-magnitude,
and thermal cost. Effectively one-way once users record video. Blocks: the
"Recording: HD Video & Audio" detail line, any video capture. Everything
proceeds; OCR's existing interactive capture is unaffected.

**7.7 Contacts (participants list, "+ Invite", real names).** Contacts TCC
+ privacy-sensitive. Alternatives: diarization labels only (current),
manual rename (exists), or Contacts. Reversible per-grant but privacy
signaling is one-way. Blocks: participant rosters with real names, invite.
Proceeds: speaker-colored participants as labels.

**7.8 Metrics & metering ("Usage this week 4h32m of 6h", "Upgrade plan",
"78 GB / 100 GB").** Local stats already exist (dictation WPM/words/apps).
Cloud metering implies accounts, billing, telemetry — the biggest one-way
door in the references and the only one that changes the product's nature.
Blocks: usage quota card, upgrade CTA, accuracy ring. Proceeds: local-only
stats presentation (already in the app).

## 8. Risk register, rollback boundaries, do-not-do

| # | Risk | Severity | Guard / rollback |
|---|---|---|---|
| R1 | Audio writer/backpressure "optimization" breaks file-time == meeting-time | 🔴 persisted media | Do not touch the writer path without G1 + a recording profile (§4). Rollback: revert the slice; audio files are append-only artifacts. |
| R2 | Re-enabling AEC or live-ASR-by-default re-triggers the 103–134 % CPU hangs | 🔴 | Keep `usesLiveASR` default false and AEC hard-off at `RecordingEngine.swift:69` (evidence: pids 25501/62139, V-prev). Any change here needs its own profile slice. |
| R3 | Migration mistakes corrupt the only DB | 🔴 | v9/v10 append-only, nullable columns, G3 upgrade-path test. Rollback: code reverts cleanly — new columns are inert to old code; never write a destructive migration. |
| R4 | New UI observers (waveform, live panel) re-introduce per-buffer MainActor publishes | 🟡 | LevelGate pattern is mandatory for any new level/peaks publish; volatile text stays out of big lists (the `MeetingDetailView` comment documents the stall). |
| R5 | Concurrency: new panels/captions observers race capture teardown | 🟡 | Panels are created-once and `setVisible`-gated (established pattern); new observers must go through existing controllers, never own capture. |
| R6 | Playback of user audio hits TCC/sandbox edge cases (file moved, retention deleted audio) | 🟡 | Player treats missing file as an empty state, never an error path; retention decision (7.3) precedes any deletion. |
| R7 | LLM subprocess sprawl (regenerate buttons, live AI, per-dictation titles) | 🟡 | G4 job owner first; 600 s watchdog stays the floor. |
| R8 | Scope creep from reference SaaS furniture (quotas, upgrade, integrations) | 🟡 | §7 keeps them out until decided; slices refuse them. |

**Rollback boundaries:** every C1–C15 slice is an independent commit/PR;
schema slices (C9, C10) are additive so a code revert leaves harmless
columns; peaks sidecars are deletable files; the player, tabs, panels, and
banner are view-layer and revert with zero data impact. The branch merges
`hold` per PLAN.md — the human drives it.

**Do-not-do (this phase):** no changes to Swift, `Package.swift`,
entitlements, schemas, settings, or durable docs beyond this file; no
one-way product contracts from §7; no re-enabling of AEC or live-ASR
default; no writer/coalescing/padding changes without a profile; no new
top-level dependency; no weakening or deletion of any test; no orphan-audio
deletion; no commits to `main`.
