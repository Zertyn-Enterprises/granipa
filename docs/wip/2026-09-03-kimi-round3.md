## P1

### P1-1 — Settings: 9 tabs → 6, solo reagrupando

- evidencia: `SettingsView.swift:7-27`. Templates es una lista de 120 px + editor apiñado (`:710-784`); API y Webhooks son dos tabs de la misma idea (integraciones); Productivity y Windows son el mismo "otro producto".
- por qué duele: 9 tabs para una app cuyo job es grabar reuniones. El usuario nuevo no distingue core de power-user. Con 6 tabs el Settings se entiende de un vistazo.
- arreglo mínimo (cero features perdidas, solo movers):
  - **Templates → AI** (son prompts del enhancement; sección bajo Speakers).
  - **API + Webhooks → Integrations**.
  - **Productivity + Windows → Extras**.
  - Resultado: General / Dictation / AI / Permissions / Extras / Integrations.

### P1-2 — Tres UIs de estado de grabación, ya divergentes

- evidencia: `RecordingHUD.swift:84-172` (expanded), `RecordingBar.swift:11-70`, `CaptionsOverlayView.swift:6-45` re-implementan por separado timer / niveles / warnings / último segmento+volátil. Ya divergen: HUD muestra último segmento, Bar no; captions no tiene timer ni Stop.
- por qué duele: cada fix de estados se hace tres veces (ya pasó con Reduce Motion: llegó a HUD y Bar, no a captions). Es deuda que crece con cada superficie nueva.
- arreglo mínimo: extraer `RecordingStatusView` (timer + levels + warnings) y `LiveTranscriptSnippet` (último final + volátil, usado por HUD y captions verbatim). Dos componentes, tres consumidores.

### P1-3 — La ventana principal no tiene motion design

- evidencia: lo único animado en toda la app principal es la transición home↔detail (`MainWindow.swift:34`) y el hover (`Theme.swift:61-73`). Grep de `.animation(`/`symbolEffect` en Home/Sidebar/MeetingDetail/EnhancedNotes: vacío.
- arreglo mínimo (barato, alto retorno profesional):
  1. Banner de detección: `.transition(.move(edge: .top).combined(with: .opacity))` + `.animation` sobre `app.detector.detectedApp` (`MainWindow.swift:21-23`) — hoy aparece de golpe.
  2. Filas de meeting: `.transition(.opacity)` en inserción/borrado de `HomeMeetingRow` (al crear/borrar meetings la lista salta).
  3. Tabs del detalle: el subrayado (`MeetingDetailView.swift:194-197`) con `matchedGeometryEffect` o al menos `.animation` en el cambio.
  - Todo gated con el patrón Reduce Motion que ya existe (`RecordingHUD.swift:6`).

### P1-4 — Menu bar: estados sí, información no

- evidencia: `GranipaApp.swift:53-58` — tres iconos (record/mic/waveform) sin más. Durante recording no hay elapsed; durante `processing` (post-Stop, diarize+enhance — el momento de mayor ansiedad) el icono vuelve a `waveform` como si nada.
- arreglo mínimo: `MenuBarExtra` con label `Text("12:34")` junto al icono mientras graba (SwiftUI lo soporta), y un cuarto estado (p.ej. `ellipsis.circle` o el statusProcessing) mientras `meeting.status == .processing` para la reunión recién parada. Cierra la paridad con los estados de Superwhisper (dot amarillo/rojo/azul/verde, verificado fase 1).

## P2

### P2-1 — Sidebar: "SPACES" siempre visible con cero folders

- evidencia: `SidebarView.swift:29-35` — header + "Add folder" aunque `app.folders` esté vacío. Para el usuario default es ~40 px y un concepto ("Spaces"/teams) que no pidió.
- arreglo mínimo: `if !app.folders.isEmpty` para el header; "Add folder" puede quedar como item dimmed sin header.

### P2-2 — MeetingDetail: tres menús chrome compitiendo con el título

- evidencia: `MeetingDetailView.swift:96-98` — folderMenu + templateMenu + actionsMenu, tres botones borderless de bajo contraste en fila sobre el título serif. Ruido visual en la vista más importante.
- arreglo mínimo: folder + template dentro del menú "⋯" (ya existe `actionsMenu`), o una sola fila de metadata `folder · template` con un solo menú. El header queda: back, fecha, ⋯.

### P2-3 — Toast: hex sueltos, posición contradictoria, siempre verde, pop duro

- evidencia: `ToastController.swift:50-59` — `0x4CD981` y `0x252B26` hardcodeados (el primero ES `Theme.statusDone`, `:24`); aparece arriba-centro (`:27-30`) cuando todos los demás overlays viven abajo; "Copied — grant Accessibility to auto-paste" (un aviso) se pinta en verde de éxito; `orderFront`/`orderOut` sin fade (`:32-38`).
- arreglo mínimo: tokens de `Theme`, abajo-centro, color semántico (success/warning), y el mismo fade `NSAnimationContext` que `DictationOverlayController.swift:41-54`.

### P2-4 — Copy stale: "~130 MB" de diarización (real: 21 MB)

- evidencia: `SettingsView.swift:376` y `README.md:103`. Medido por GLM en fase 1: 21 MB cacheados en disco.

## Nota de dirección (no es hallazgo, es para el rediseño)

El lenguaje visual ya tiene identidad: serif para títulos, naranja `0xF05423` como único acento, cards con border sutil. El rediseño debería **apretar esa identidad, no reemplazarla**: donde más se nota "aficionado" no es la paleta sino la consistencia de superficies (hex sueltos fuera de Theme — P2-3 es el ejemplo), la densidad del chrome (P2-2) y la ausencia total de motion en la ventana principal (P1-3). Arreglados esos tres, la app se lee profesional sin tocar una sola tipografía.
