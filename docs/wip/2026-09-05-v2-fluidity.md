## Changes and evidence

### Library card excerpt — Grok, integrated as `9bc0387`

Home and Notes previously parsed an entire Markdown document on each card body
evaluation, then displayed only two plain lines. The shared parser now has a
bounded prefix path. Full-document parsing and displayed excerpt semantics stay
the same. Tests cover leading blanks, fallback/summary precedence, long notes,
real ephemeral database roundtrip, and the number of visited lines.

Identical input: two visible lines plus 20,000 filler lines.

| Measurement | Before | After |
|---|---:|---:|
| Excerpt helper, minimum of five measurements | 46,611,417 ns | 7,875 ns |
| Lines classified for the excerpt | 20,002 | 2 |

The comparative performance assertion failed before the implementation. Both
implementations return `Hello\nWorld`. This is an adversarial long-note
microbenchmark; it is not a whole-app speedup. Long leading blanks or a single
very long displayed line still require reading the relevant prefix.

### Transcript render work — GLM, integrated as `7d1ed4e`

The transcript view previously recomputed the complete set of current segments
inside every realized row closure. Filtered rows and speaker names were also
recomputed by several consumers. They are now immutable locals shared within
one body evaluation. No cache, query algorithm, scroll cadence, selection,
playback or stored data changed.

A standalone optimized harness uses the production TranscriptQuery helpers and
models the old/new call multiplicities on deterministic synthetic segments.
It does not render SwiftUI. Example results:

| Segments / realized rows / filter | Before µs/modelled update | After µs/modelled update |
|---|---:|---:|
| 1,000 / 50 / none | 247.6 | 52.1 |
| 10,000 / 50 / none | 2,965.4 | 543.4 |
| 10,000 / 50 / search + speaker | 26,256.1 | 5,451.6 |

The harness models autoscroll **on**, whereas the app defaults it to off.
These are helper-work proxies, not measured UI refresh times or an exact count
of SwiftUI body evaluations. Actual lazy-row realization and compiler elimination
of unused benchmark values can affect the magnitude. The source-level elimination
of repeated full-array computations is independently visible in the diff.

### Audio-test scheduling repair — GLM, integrated as `a35670f`

The full parallel suite reproduced a pause assertion failure when a 0.45-second
real audio fixture ended before MainActor test resumption. The fixture is now
30 seconds and the test waits for observable progress, then pauses synchronously.
The EOF section seeks to the tail; it does not wait 30 seconds. Every original
assertion remains, duration bounds track the new fixture, and a playing-state
precondition was added. Product playback code is unchanged.
